# Internal positioning notes

Team working notes—not landing-page copy or a submission draft. This file is
not served by the app; it is still visible to anyone who can read this repo.

## Track intent

We are targeting the **“Best Heist Theme Project”** track. That is our team's
positioning choice, not a claim that entry, eligibility, or an award has been
confirmed. UI polish supports this track; it isn't a replacement for it.

The public pitch is **AI-assisted physical red-team reconnaissance**:
permission-based observation, evidence collection, asset-value appraisal,
and a team debrief. Do not pitch this as “robbing a room,” a “thief's shopping
list,” or a tool that recommends what to steal.

## Why the heist theme still fits

The assessment is staged like a heist film: an advance scout, a field
operator, a dispatch desk, radio check-ins, a shared case file, and a dramatic
reveal. Film-noir typography, evidence markers, stamps, music, and voice lines
carry the theme without changing the legitimate purpose of the exercise.

If judges ask about the theme, say: “We borrowed the heist crew's coordinated
reconnaissance workflow and turned it into an authorized red-team debrief.”

## Copy conventions

| Existing themed term | What it means in the pitch |
| --- | --- |
| Crew | Authorized assessment team |
| Casing / scouting the room | Reconnaissance within the approved exercise area |
| Loot / take | Observed assets / summed estimated asset value |
| Top five / lineup | Assets ranked by market-value estimate, not security risk |
| Reveal | Assessment debrief |
| Loot manifest | Shareable asset evidence report |
| Bail / evacuation ETA | Simulated exercise-time cue, not a real detection or safety estimate |

Keep “The Appraisal Job” name and the noir visual language. Existing service
names, JSON keys, and theatrical UI labels don't need a compatibility-breaking
rename for this pitch change. Future narrator scripts should use an authorized
exercise context. The current grounded dispatch and narrator line bank retain
their heist persona; this pitch change does not rewrite their runtime scripts.

## Claim boundaries

- Pitch the existing identify → appraise → deduplicate → document → debrief
  workflow. Don't present proposed backlog features as implemented.
- Estimated market value isn't exploitability, expected loss, or a validated
  security-risk score. An observed asset isn't automatically a vulnerability.
- Don't claim verified physical access, autonomous intrusion, detection
  prediction, security-control testing, or automated remediation.
- Clearly distinguish live observations and price sources from model estimates
  and offline/scripted demo data. Hardware readiness claims still follow the
  verification ledger, not the pitch.
- Use team-owned or explicitly approved demo props. No property is removed;
  the demonstration collects observations, not possessions.
